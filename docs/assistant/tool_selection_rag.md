# 비서 토큰 줄이기: 말에 맞는 도구·규칙·지식만 보내기 (요구사항, 2026-11-09)

**담당:** C파트 채림 (서버) · A파트 재휘 (키워드 표·지식 조각·시험) · **동결 11-13(금)**

지금 서버는 제미나이를 부를 때마다 **시스템 규칙 전체(약 1,790자)와 도구 7개 설명 전체(약 1,650자)** 를 보낸다. 도구를 부르고 결과를 받는 왕복이 질문 하나에 최대 5번이라, 같은 글이 그만큼 되풀이된다.
말을 먼저 보고 **필요한 도구와 규칙 조각만 고르고(R2·R3), 앱에 대한 질문이면 필요한 설명만 찾아 붙이면(R4, 증강검색)** 매 왕복 보내는 양을 줄일 수 있다. 다만 실제 토큰 수는 아직 잰 적이 없어서 R1부터 한다.

## 다 됐다는 기준

| # | 기준 | 어떻게 확인 |
|---|---|---|
| 1 | 비서 점검 통과 수가 지금보다 떨어지지 않음 (지금 29/33) | `python3 scripts/eval_assistant.py` 고치기 전·후 |
| 2 | 질문 하나의 입력 토큰 평균이 30% 이상 줄어듦 | R1 기록으로 고치기 전·후 비교 |
| 3 | 응답 시간이 늘지 않음 | 점검 결과의 걸린 시간 |
| 4 | 도구를 잘못 골라도 지금보다 나빠지지 않음 | R5 안전장치가 다시 물음, 그 횟수를 셈 |
| 5 | 점검 질문 35개 모두, 고른 도구 안에 필요한 도구가 다 들어 있음 | R6 단위 테스트 (제미나이 안 부름) |

## 범위 밖

- MCP (토큰이 줄지 않음. 같은 도구 설명이 그대로 제미나이에 들어감)
- 벡터 DB·임베딩 (R4는 MySQL 전문 검색으로 시작. 임베딩은 동결 뒤에 따로 판단)
- 대화를 서버에 저장하기, 제미나이에 좌표·게스트 번호·기록 원본 보내기 (NFR-07, `consent.md` 4번)

## R1. 토큰 재기 (먼저, 11-09~10)

- 제미나이 응답의 `usageMetadata`(`promptTokenCount`, `candidatesTokenCount`, `totalTokenCount`)를 왕복마다 받아 질문 하나 단위로 더한다.
- 로그 한 줄: 모델, 왕복 수, 입력·출력 토큰 합, 보낸 도구 이름, R5로 다시 물었는지.
  **말 원문과 게스트 번호는 남기지 않는다.**
- `/api/assistant` 응답에 `usage: {prompt, output, rounds, tools, retried}` 칸을 더한다. 앱은 무시하면 되고, A파트 점검 스크립트가 이 칸을 모아 전·후를 비교한다.
- 규칙이 먼저 처리해 제미나이를 안 부른 질문(급한 말, 확인 답, 인사 등)은 `usage`가 0이다. 이것도 셈에 넣는다.

## R2. 말에 맞는 도구만 보내기 (`ToolPicker`)

`GeminiBrain`의 `gemini.chat(SYSTEM, contents, DECLARATIONS)`에서 `DECLARATIONS` 대신 고른 것만 보낸다.

| 묶음 | 말에 이런 게 있으면 (예) | 보낼 도구 |
|---|---|---|
| 길 | 가자, 가고 싶어, 어떻게 가, 데려다, 집에, ~까지 | `search_place`, `recommend_trip` |
| 가까운 곳 | 어디야, 근처, 가까운, 화장실, 쉼터, 편의점, 경찰서, 비상벨, 지하철역 | `find_nearby` (+ 가게·장소 이름이면 `search_place`) |
| 가게 | 밥, 먹을, 카페, 약국, 국밥, 은행 | `search_place` |
| 내 정보 | 휠체어 안 타, 다리 다쳐, 지팡이, 계단, 모드, 내 정보, 기록 | `get_my_info`, `update_my_info` |
| 지도 표시 | 보여 줘, 숨겨, 지도에, 표시 | `set_map_layers` |
| 신고 | 공사 중, 막혔어, 고장, 턱이 높아, 위험해, 신고 | `report_problem` |
| 안 걸림 | 위 어디에도 안 걸림 | **7개 다** (지금과 같음) |

- 여러 묶음이 걸리면 합친다. 예: "화장실 들렀다 집에 가자" → 가까운 곳 + 길.
- 이어지는 말("거기 몇 층이야", "그걸로 가자")이면 바로 전 질문에 쓴 도구를 더한다 (`conversationId`에 담긴 마지막 도구).
- 한 질문 안에서는 첫 왕복에 고른 목록을 끝까지 쓴다.
- 키워드 표는 코드에 박지 않고 파일 하나(`src/main/resources/assistant/tool_groups.json`)로 둔다. A파트가 점검 결과를 보고 고친다.

## R3. 규칙도 조각으로 나눠 보내기 (증강검색 1단계)

지금 `SYSTEM` 글을 조각으로 나눠, **공통 조각은 늘** 보내고 **나머지는 R2에서 고른 묶음에 딸린 것만** 붙인다.

| 조각 | 지금 `SYSTEM`의 어느 줄 | 언제 보내나 |
|---|---|---|
| 공통 | 역할 한 줄, [지켜야 할 규칙] 전부 (지어내지 않기·못 하는 일·급한 말·숫자는 도구 결과만·광주 밖·애매하면 한 가지만 되묻기), [말투]의 존댓말·세 문장·어린이·어르신 | 늘 |
| 길 | search_place → recommend_trip 한 번, 거리·동네 이름은 그대로 search_place, sentence·because 쓰는 법, 쉴 곳 개수·저상버스 말 빼지 않기, 이동 수단 말 없이 시간만·대중교통 순서 | 길 묶음 |
| 가게 | 가게는 search_place, 여럿이면 짧게 묻기, 먹을 종류 되묻기 | 가게 묶음 |
| 가까운 곳 | find_nearby 대상 목록, 카페·음식점은 search_place, 모드는 묻지 않기 | 가까운 곳 묶음 |
| 내 정보 | 되묻기 전 get_my_info, 처음 쓰는 사람 질문 하나씩, 잠깐 바뀐 몸 상태는 언제까지 꼭 묻기(모르면 7일) | 내 정보 묶음, 처음 쓰는 사람 |
| 저장 | 저장하는 도구는 서버가 확인을 묻고, 저장됐다고 말하지 않기 | 내 정보·지도 표시·신고 묶음 |

- 조각은 파일(`src/main/resources/assistant/rules/*.txt`)로 두고, 서버가 켤 때 읽는다.
- "안 걸림"이면 지금처럼 전부 보낸다.

## R4. 앱에 대한 질문은 필요한 설명만 찾아 붙이기 (증강검색 2단계)

"내 기록 어디에 저장돼?", "왜 이 길이야?", "휠체어 모드는 뭐가 달라?", "AI가 내 위치 알아?" 같은 질문은 도구가 아니라 **우리가 정해 둔 설명**으로 답해야 한다. 이 설명을 규칙에 다 넣으면 매번 길어지므로, 따로 두고 **필요할 때만 찾아서** 붙인다.

**지식 조각 표 `assistant_knowledge` (A파트가 만듦, 학교 DB)**

| 칸 | 내용 |
|---|---|
| `id` | 번호 |
| `topic` | 짧은 주제 (예: 기록 저장, AI에 보내는 것, 휠체어 기준, 못 하는 일) |
| `keywords` | 찾을 때 쓸 말 (쉼표) |
| `body` | 비서가 그대로 근거로 쓸 설명, **300자 이하** |
| `source` | 근거 문서 (`consent.md` 1번, 요구사항 6.2, `no_tool_policy.md` 등) |
| `updated_at` | 고친 날 |

- 처음 넣을 것 (A, 11-10까지, 30개 안팎): `consent.md`(기록 남기는 것·남기지 않는 것·지우기·AI에 보내는 것), 요구사항 6.2 모드별 기준, `no_tool_policy.md` 다섯 가지 경우, 자주 나올 질문.
- 사용자 개인 자료는 넣지 않는다 (공용 설명만).

**서버가 할 일 (C)**

- MySQL 전문 검색(`FULLTEXT ... WITH PARSER ngram`, 한국어용)으로 `keywords`+`body`를 찾아 **점수가 기준 넘는 것 3개까지, 합 900자 이하**만 사용자 말 앞에 `[참고]`로 붙인다.
- 언제 찾나: R2에서 "안 걸림"이거나, 말에 왜·어떻게·뭐가 달라·저장·AI·개인정보 같은 질문 말이 있을 때. 길 찾기·가까운 곳처럼 도구로 끝나는 말에는 붙이지 않는다.
- 규칙 조각에 한 줄 더: "[참고]에 있는 내용만 근거로 말하고, 없으면 모른다고 한다."
- 찾기는 서버 안에서만 한다. 제미나이에는 찾은 설명 글만 간다.

## R5. 안전장치

- 도구를 7개보다 적게 보냈는데 제미나이가 ① 도구를 하나도 안 부르고 "못 해요·그건 안 돼요"처럼 답하거나 ② 없는 도구 이름을 부르면, **7개 전부와 규칙 전부를 붙여 한 번만** 다시 묻는다.
- 다시 물은 횟수를 R1 로그·`usage.retried`에 남긴다. 많으면 A파트가 키워드 표를 고친다.
- 제미나이가 안 되면 지금처럼 규칙(RuleBrain)이 같은 도구를 부른다. 바뀌지 않는다.
