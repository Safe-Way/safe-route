# 도구가 없는 요청을 처리하는 법 (2026-11-06)

말로 받은 요청에 맞는 도구가 없을 때 비서가 하는 일. 가장 위험한 것은 **못 한 일을 했다고 지어내는 것**이라, 처리 방법을 미리 정해 둔다.
앱에서는 MCP를 거치지 않는다. 휴대폰 음성 인식 → 우리 서버 `/api/assistant` → 제미나이 함수 호출 → 우리 코드(도구 7개) 순서로 처리한다.

## 다섯 가지 경우
| 경우 | 예 | 비서가 하는 일 | 못 한 요청 표(030) |
|---|---|---|---|
| ① 비슷한 도구로 대신할 수 있음 | "약국 어디야", "은행 가고 싶어" | 우리 시설 목록에 없어도 `search_place`(카카오 장소 검색)로 찾음. "가까운 약국은 ○○약국, 300m예요" | 남기지 않음 |
| ② 말로만 답하면 되는 것 | "고마워", "너 뭐 할 수 있어?" | 짧게 답하고 할 수 있는 일 예시를 버튼으로 | 남기지 않음 |
| ③ 우리가 못 하는 일 | "택시 불러 줘", "병원 예약해 줘" | **했다고 하지 않음.** "택시 부르기는 아직 못 해요. 가까운 택시 타는 곳이나 버스를 알려 드릴까요?" — 할 수 있는 다른 방법을 하나 제안 | `no_tool` |
| ④ 급한 일 | "넘어졌어", "누가 따라와", "숨이 차" | 도구가 없어도 바로 "112에 전화할까요? 보호자에게 위치를 보낼까요?" + 큰 버튼. AI에 맡기지 않고 **서버 규칙이 먼저** 낱말을 보고 거름 | 남기지 않음 |
| ⑤ 길찾기와 상관없는 것 | "오늘 주식 어때", "노래 불러 줘" | "저는 길 안내 비서라 그건 못 도와드려요" 한 줄로 끝내고 길찾기로 돌림 | `off_topic` |
| (알아듣지 못함) | 말이 끊기거나 소음 | "다시 한 번 말씀해 주세요" + 자주 쓰는 말 예시 버튼 | `not_understood` |

## 제미나이에게 처음에 주는 규칙
1. 도구가 없으면 절대 했다고 말하지 않는다. "○○했어요"는 도구가 성공했을 때만 말한다.
2. 못 하는 일은 못 한다고 말하고, 할 수 있는 다른 방법을 하나 제안한다.
3. 급한 말(넘어짐, 위험, 아픔, 숨이 참)이 나오면 다른 일보다 먼저 112·보호자를 묻는다. (서버 규칙이 먼저 걸러도, 제미나이도 같은 규칙을 지킨다)
4. 길 안내와 상관없는 질문에는 길게 답하지 않는다.
5. 숫자·이름·시간은 도구 결과에서만 쓴다.

## 못 한 요청 모으기 (030 `assistant_unmet`)
- 남기는 것: 날짜, 모드, 요청 말(전화번호·이름처럼 보이는 것은 지움), 종류(`no_tool`·`off_topic`·`not_understood`), 짧은 주제(택시, 병원 예약 등), 대신 제안한 것
- 남기지 않는 것: 게스트 번호, 위치, 시각
- `assistant_unmet_top` 뷰: 주제별로 몇 번 나왔나 → 다음에 만들 도구 1순위
- 발표에서 "비서가 쓸수록 무엇이 필요한지 스스로 알려 준다"로 보여 준다. 학교 DB에 만들어 시험했다(시험 줄은 지움).

## 시험 질문
`eval_questions.json` 31~35번이 이 경우들이다(약국, 택시, 넘어짐, 주식, 고마워).
