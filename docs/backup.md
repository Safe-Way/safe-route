# DB 자동 백업

2026-11-24. 학교 DB를 바꾸는 일(Flyway V37~V41 등) 전에 되돌릴 수 있게 하려고 만들었다.

## 무엇을, 언제

| 종류 | 언제 (서버 cron) | 무엇 | 보관 |
|---|---|---|---|
| daily | 매일 03:30 | 사람이 만든 기록 표: 내 정보·걷기 속도·걷기 측정·이동 기록·내 지도 설정·보호자 공유·게스트 토큰·신고·신고 사진·비서가 못 한 요청·호출 수·Flyway 기록·지도 시설 사전·행사·적재 현황 | 14개 |
| full | 매주 일요일 04:10 | 모든 표 (시설·도로망 같은 공공데이터 포함, 큼) | 2개 |

- 공공데이터 표는 스크립트로 다시 넣을 수 있지만 API 하루 한도 때문에 며칠이 걸려서, 주 1회 전체 백업으로 지킨다.
- 서버 `~/safe-route/backup/`에 남고, 폴더·파일은 본인만 읽는다. **개인정보가 들어 있다.**
- 서버가 하나라 서버·디스크가 통째로 망가지면 서버 안 백업도 같이 사라진다. 그래서 **주 1회 서버 밖(노트북)으로 복사**하고, **한 달에 한 번 되살려 본다.**

## 처음 한 번 (서버)

배포(`deploy.yml`)가 `backup_db.sh`를 `~/safe-route/`에 올린다. 서버에 접속해서 한 번만 실행한다.

```bash
bash ~/safe-route/backup_db.sh install   # crontab 에 두 줄을 넣는다 (다시 해도 한 번만)
bash ~/safe-route/backup_db.sh daily     # 바로 한 번 떠 보기
bash ~/safe-route/backup_db.sh status    # 남은 백업과 기록 보기
```

- DB 접속 정보는 `~/safe-route/app.env`에서 읽는다. 따로 적을 것이 없다.
- `mysqldump`는 `mysql:8.0` 도커 이미지의 것을 쓴다(서버에 따로 깔지 않음).
- 공용 DB라 표를 잠그지 않는 방식(`--single-transaction`)으로 뜨고, 우리 계정 권한 밖의 정보(트리거·테이블스페이스)는 뺀다.
- 끝까지 떴는지(`Dump completed` 줄, gzip 검사)를 확인하고, 실패하면 `backup.log`에 남기고 파일을 지운다.

## 주 1회: 서버 밖으로 (노트북)

```bash
SR_SSH=<계정>@<서버 주소> SR_SSH_PORT=<포트> bash scripts/pull_backup.sh
```

- 최신 daily·full 하나씩을 `~/safe-route-backup/`(저장소 밖)에 받는다. 비밀번호는 한 번 묻는다.
- 접속 정보는 저장소가 공개라 적지 않는다. 실행할 때 넣는다.
- 받은 폴더를 클라우드 동기화 폴더나 저장소 안에 두지 않는다.

## 한 달에 한 번: 되살려 보기 (노트북)

```bash
bash scripts/check_backup.sh ~/safe-route-backup/daily/<파일>.sql.gz --compare
```

빈 MySQL 8.0(도커)에 넣어 보고 표마다 줄 수를 지금 학교 DB와 나란히 보여 준다(학교 DB는 읽기만). 백업 뒤에 늘어난 줄만큼 지금 DB가 많은 것은 정상이고, 백업 쪽이 0인데 지금 DB가 많으면 `← 백업이 비었음`이 붙는다.

2026-11-24 노트북에서 시험: daily 백업 13개 표(1초, 16KB) → 되살린 줄 수가 학교 DB와 모두 같음. 겹쳐 돌리면 건너뛰고, 보관 개수를 넘으면 오래된 것부터 지움. full은 아직 서버에서 처음 도는 것을 기다린다(`status`로 확인).

## 되돌릴 때

```bash
gzip -dc <파일>.sql.gz | mysql -h <주소> -P <포트> -u <계정> -p <DB 이름>
```

백업 파일은 표마다 `DROP TABLE IF EXISTS` 뒤 다시 만든다. **그 표들의 지금 내용이 백업 시점으로 바뀌므로**, 팀에 먼저 알리고, 되돌리기 직전 상태도 `backup_db.sh daily`로 한 번 더 떠 둔다.
